# CipherVault 架构

CipherVault 是 Windows-only 的本地密码管理器。应用由四个项目组成：

- `CipherVault.Core`：模型、领域接口、事件和异常，不依赖 WPF 或基础设施。
- `CipherVault.Infrastructure`：Argon2id、AES-256-GCM、SQLite、备份、导入导出和 Win32 安全互操作。
- `CipherVault.UI`：WPF View、ViewModel、主题、转换器和控件。
- `CipherVault.App`：依赖注入、单实例、启动/退出、托盘和窗口生命周期。

## 运行时数据流

1. 用户选择 `.cvault` 并输入主密码。
2. Argon2id 根据文件头参数派生 256 位密钥。
3. AES-256-GCM 验证并解密 SQLite payload，使用 SQLite deserialize API 直接装载到进程内的私有内存数据库；journal 与临时表也固定使用内存模式，不创建明文 session 文件。
4. 应用持有打开的内存 SQLite 连接；密码字段仍以每条记录独立的 AES-GCM 数据块存储，只在显示、复制或导出时短暂解密。
5. 条目保存、批量管理和 CSV 导入先在单个 SQLite 事务中提交；内容变化在短延迟窗口内合并，只执行一次数据库序列化与整库加密。访问时间等低优先级元数据使用更长的合并窗口。
6. 加密结果以目标目录中的加密临时文件写入并原子替换 `.cvault`。锁定或退出前强制刷新尚未持久化的变化，然后关闭内存数据库并清零保险库密钥。

## UI 状态

`MainWindowViewModel` 协调三栏布局：左侧保险库/分组导航，中间条目搜索列表，右侧详情、编辑和历史记录。锁定状态会清空列表和详情，取消搜索任务，并释放仓库会话。全局搜索复用同一仓库，但不会跨线程并发使用 SQLite 连接。

## 持久化原则

- 所有条目、分组、标签、历史和回收站操作都通过 `IVaultRepository`。
- 删除条目先进入回收站；可恢复、永久删除，并在解锁后清理超过 30 天的项目。
- 删除分组会在事务中把直属条目和子分组移到根级，避免悬空引用。
- 条目详情、批量管理和批量导入会把相关写操作合并到一个事务，并在提交后只触发一次加密持久化通知。
- 配置和保险库写入使用同目录临时文件并刷新到磁盘后替换目标。
- 自动备份保存完整的加密 `.cvault` 文件，而不是不可恢复的内部导出格式。

## 扩展边界

凭证类型、自定义字段、标签和分组是领域模型的一部分。新增界面功能应先扩展 Core 接口，再由 Infrastructure 实现，ViewModel 不应直接访问 SQLite 或 Win32 API。
