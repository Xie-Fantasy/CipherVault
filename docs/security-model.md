# 安全模型与已知限制

## 保护目标

CipherVault 主要保护未解锁保险库在磁盘、普通备份介质和离线窃取场景中的机密性与完整性，并减少解锁期间密码暴露的时间。它不能在已被管理员级恶意软件完全控制的 Windows 会话中提供绝对安全。

## 已实现措施

- 主密码通过 Argon2id 派生密钥，默认参数为 64 MiB、3 次迭代、并行度 4。
- `.cvault` payload 使用 AES-256-GCM；认证失败会按保险库损坏处理。
- 解锁后的 SQLite payload 只装载到私有内存数据库，journal 和临时表使用内存模式；当前版本不创建明文 session 数据库。启动时仍会尽力清除旧版本遗留的 session 文件。
- 每个密码字段使用由保险库密钥和条目 ID 派生的独立密钥再次 AES-GCM 加密。
- 活跃保险库密钥保存在 `VirtualLock` 的非托管内存中，锁定时使用 `CryptographicOperations.ZeroMemory` 清零后释放。
- 保存使用原子替换，备份保留完整加密文件和 SHA-256 元数据校验。
- 剪贴板只在内容仍与本次复制相同时清除，避免覆盖用户后来复制的内容。
- 截屏防护默认关闭，用户可在“设置 → 安全”中开启；开启后所有应用窗口请求 `WDA_EXCLUDEFROMCAPTURE`，调用失败只记录非敏感诊断信息。
- 主密码失败采用递增延迟和临时锁定；会话锁屏、空闲、最小化和可选失焦会触发锁定。
- Windows Hello 快速解锁默认关闭，可在设置的“安全”页启用。应用使用 Microsoft Passport Key Storage Provider 创建不可导出的 RSA 私钥，以 OAEP-SHA256 包装每个保险库的派生密钥；磁盘上只保存密文，私钥解密操作会要求 Windows Hello 的 PIN、面容或指纹验证。主密码和恢复密钥始终保留为兜底。
- 旧版仅用 DPAPI 保存密钥的方案不能把解密与 Hello 验证在密码学上绑定，应用启动时会清理其遗留 `.dat` 数据。

## 恢复与备份

新保险库生成 12 个 BIP39 英文恢复词。恢复词通过 BIP39 PBKDF2 派生恢复密钥，用于解开文件头中的 32 字节保险库密钥副本。恢复成功后必须设置新主密码，应用会轮换盐、主密钥、密码字段和恢复块。

自动/手动备份是完整 `.cvault` 文件，可用应用的“恢复备份”操作打开。CSV 和 KeePass XML 是迁移格式，含明文密码，界面会明确警告。

## 已知限制

- 解锁期间，账号、网址和备注等可搜索字段会以明文存在于进程的 SQLite 内存页中；同一用户权限的进程注入、管理员级内存读取、页面文件和系统崩溃转储仍可能捕获它们。纯内存数据库消除了应用主动写出的明文 session 文件，但不能把已失陷的操作系统变成可信环境。
- WPF 和 .NET 的托管 `string` 无法可靠原地清零。敏感值尽量使用 `byte[]` 或非托管内存，但输入框和短暂显示仍可能产生托管字符串。
- `SetWindowDisplayAffinity` 不是 DRM，也不能阻止相机、内核级捕获或所有远程桌面实现。
- Windows 剪贴板管理器可能在应用清除前保存历史副本。
- 文件头中的失败次数和锁定时间由 SHA-256 检错但未用秘密密钥认证，能够修改文件的离线攻击者可能重置计数；抵御离线猜测的核心仍是 Argon2id 和主密码强度。
- 强制 GC 不能保证敏感托管对象立即从物理内存消失，因此不把它视为安全边界。

## 安全使用建议

- 主密码允许 6–128 个字符，建议使用容易记住且唯一的长口令；恢复词应离线手抄并与电脑分开保存。
- 不要在不受信任或已感染的 Windows 环境中解锁保险库。
- 明文导出完成迁移后应安全删除，并检查同步盘、回收站和文件历史。
- 至少保留两份加密 `.cvault` 备份，并定期实际执行恢复验证。
